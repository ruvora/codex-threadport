# RUVORA ThreadPort 설계 초안

- 작성일: 2026-09-06
- 상태: 계획만 수립. 제품 구현·배포·실계정 간 이전 검증 미완료.
- 제품명: RUVORA ThreadPort(가칭)
- 문서 범위: 대화에서 합의한 요구사항, 기술 실험 결과, 설계 및 구현 관문을 보존한다.

상세 계약: [ThreadPort 구현 설계 v0.2](THREADPORT_CONTRACTS.md). 상위 제품: [RUVORA Workspace 기획](RUVORA_WORKSPACE_DESIGN.md). 이번 상세화는 설계 재개이며, 독립 이력의 안전한 이전 관문은 여전히 미통과다.

## 1. 목적과 사용자 요구

사용자가 자신의 Codex 세션을 선택한 완료 시점까지 내보내고, 다른 사람이 자신의 환경과 인증으로 독립적으로 이어 작업하게 한다. 요약 전달이나 원격 작업 공간 초대가 아니라, 저장된 이력을 기반으로 한 세션 이전·포크가 목표다.

여기서 맥락 보존은 저장된 대화·실행 기록의 연속성을 뜻한다. 모델의 숨겨진 사고 상태 복제, 모든 과거 내용의 무제한 컨텍스트 포함, 동일한 답변 재현을 보장하지 않는다. 이미 압축·누락된 정보는 원본에서 복구 가능한 범위를 먼저 확인한다.

## 2. 제품 경계

| 제품 | 책임 |
| --- | --- |
| ThreadHub | 작업 실행·조정·결과 통합 및 관리 중인 세션의 실행 안전성 |
| ThreadGraph | 스레드 관계·맥락·출처 분석 |
| ThreadPort | 세션 내보내기·검증·가져오기·계보 보존 |

ThreadPort는 독립 플러그인으로 설계한다. Hub 없이도 동작하되, Hub 관리 세션은 상태와 작업 공간을 Hub에 확인한다. 관리 중인 세션의 실행권을 빼앗거나 두 번째 쓰기 주체가 되어서는 안 된다.

### 첫 버전 포함 범위

- 로컬 패키지 파일 생성 및 가져오기
- 완료 Turn 기준의 명시적인 공유 범위
- 새 로컬 세션 ID와 원본 계보 기록
- 포함 내역·호환성·위험 미리보기와 사용자 승인
- 검증된 이력 형식만 지원하는 대화 전용 MVP

### 첫 버전 제외 범위

- 공유 서버, 초대 링크, 원격 세션 공동 실행
- 원본 삭제·아카이브, 여러 대화의 물리적 병합
- 토큰·API 키·원래 실행 권한 이전
- 자동 코드 실행, 자동 도구 설치, 자동 결과 병합
- 실제로 검증하지 않은 Codex 버전·환경에 대한 호환 보장

## 3. 기술 검증 기록

실험 환경은 Codex CLI 0.153.1, 같은 PC의 독립된 Codex 저장 디렉터리, 별도 App Server 프로세스, 로컬 모의 Responses 서버였다. 개인 세션·인증 정보는 사용하지 않았다. 실제 모델의 이해 능력이나 타인 계정 인증 테스트가 아니다.

| 검사 | 관찰 결과 |
| --- | --- |
| 동일 환경에서 완료 Turn까지 포크 | 분기점까지 이력이 유지되고 이후 Turn은 제외됨 |
| 포크에서 후속 요청 | 이전 맥락이 실제 모델 요청 입력에 포함됨 |
| 원본 독립성 | 포크 후속 실행이 원본 이력을 변경하지 않음 |
| 작업 파일 자동 복제 | 수행되지 않음 |
| 독립 저장 환경에 세션 ID만 전달 | 접근 실패 |
| 외부 rollout 경로를 지정해 가져오기 | 해당 실험에서 실패. 설치 스키마의 경로 필드만으로 성공을 보장할 수 없음 |
| 포크 rollout 파일만 받는 저장소에 복사 | 원본 rollout 참조 누락으로 실패 |
| 테스트 원본·포크 이력을 함께 복사 | 받는 환경에서 새 포크 생성·후속 실행 성공 |
| 보내는 프로세스 종료 후 받는 쪽 실행 | 성공 |
| 받는 프로세스 재시작 후 재개 | 공유 맥락과 받는 쪽 추가 맥락 유지 |
| 공유 범위 밖 정보 보호 | 전체 원본 복사 시 실패. 모델 입력에서 제외돼도 받는 저장소 파일에는 남음 |

마지막 성공은 내부 저장 파일 복사를 포함한 실험이며, 공식적으로 보장된 내보내기·가져오기 기능이라는 의미가 아니다. 실제 다른 PC, 각자의 계정 인증, Codex 앱에서의 발견·열기는 미검증이다.

### 실험 자료 위치

- 동일 환경 실험: `/tmp/ruvora-fork-probe.uBOsmd/probe.mjs`
- 독립 저장 환경 실험: `/tmp/ruvora-fork-probe.uBOsmd/transfer-probe.mjs`
- 설치 스키마: `/tmp/ruvora-fork-schema.983HcM/v2/ThreadForkParams.json`

위 자료는 임시 경로라 사라질 수 있다. 구현 착수 시 재현 가능한 테스트를 제품 레포로 정리해야 한다. 테스트 스크립트의 `importByRolloutPath` 고정 성공 표시는 이후 오류 유무를 반영하도록 수정했다. 실제 성공 경로는 원본 계보 파일을 받는 저장소로 복사한 뒤 ID로 포크한 경로였다.

참고: [Codex App Server 문서](https://learn.chatgpt.com/docs/app-server#threads). 이 문서는 당시 실험 결과의 기록이며 최신 API 지원 여부는 구현 시 재확인한다.

## 4. 최우선 기술 관문: 독립 이력

포크 파일은 원본 이력을 참조할 수 있다. 원본 전체를 보내는 방식은 공유 경계를 위반하므로 제품 방식으로 채택하지 않는다.

History Materializer는 다음 계약을 만족해야 한다.

1. 선택한 완료 시점까지 필요한 이력만 포함한다.
2. 보내는 환경이나 원본 파일에 접근하지 않고 재개할 수 있다.
3. 이후 Turn의 내용이 패키지·첨부·메타데이터 어디에도 포함되지 않는다.
4. 메시지 순서·역할·도구 호출과 결과의 대응을 보존한다.
5. 처리 불가능한 데이터는 조용히 생략하지 않고 실패 또는 명시적인 제한으로 표시한다.
6. 요약·재주입을 사용했다면 원본 포크와 동일하다고 주장하지 않는다.

공식 API로 이 조건을 만족할 수 있는지 먼저 검증한다. 내부 저장 형식 변환이 불가피하면 버전별 어댑터로 격리하며, 알 수 없는 형식은 거절한다. 아직 이 관문은 통과하지 않았다.

## 5. 사용자 흐름

### 내보내기

1. 세션과 마지막 완료 Turn을 선택한다.
2. 실행 상태·권한·이력 형식·원본 참조를 검사한다.
3. 포함 이력, 제외 항목, 파일과 환경 정보, 위험을 미리 보여준다.
4. 사용자 승인과 해당 스냅샷을 결합한다.
5. 독립 이력과 패키지를 생성하고 범위·무결성을 검사한다.
6. 검사에 성공한 파일만 사용자에게 전달한다.

### 가져오기

1. 패키지를 코드 실행 없이 검사한다.
2. 출처 주장, 포함 내용, 변경·누락, 필요한 환경을 보여준다.
3. 받는 사용자가 대상 작업 공간과 권한을 선택한다.
4. 승인 후 별도 위치에 준비하고 새로운 세션으로 등록한다.
5. 받는 사용자의 인증으로 재개한다. 가져오기 자체가 실행 승인은 아니다.
6. 결과와 새 세션·원본 계보를 기록한다.

## 6. 제안 패키지

확장자와 스키마는 제안이며 확정하지 않았다.

```text
session.ruvora-port
├── manifest.json
├── history/
├── workspace/
├── environment.json
├── provenance.json
└── checksums.json
```

- `manifest`: 형식 버전, 소스 Codex 버전, 분기점, 포함 범위, 변환·제외 내역
- `history`: 외부 원본 의존성이 해소된 이력
- `workspace`: 명시적으로 선택한 코드·변경·결과물. 대화 전용 MVP에서는 제외
- `environment`: 필요한 런타임·도구·지침과 받는 환경에서 재설정할 항목
- `provenance`: 원본과 분기점의 계보. 원래 사용자 경로 등 불필요한 식별자는 최소화
- `checksums`: 파일 무결성 검사. 체크섬은 보내는 사람의 신원을 인증하지 않음

게시자 서명, 암호화, 대용량 파일 처리 방식은 후속 설계 항목이다. 파일이 상대에게 전달된 뒤에는 접근 회수가 불가능하다는 점을 안내한다.

## 7. 대화와 작업 공간의 시점

대화 분기 시점과 파일 스냅샷은 별도로 취급한다. 과거 Turn 당시 파일 스냅샷이 없다면 현재 파일을 과거 상태로 표시하지 않는다. 불일치를 사용자에게 알리고 선택을 받거나 내보내기를 보류한다.

작업 공간 이전 단계에서는 커밋, 미커밋 변경, 선택한 미추적 파일, 결과물, 경로 재연결을 검증한다. 파일 전체나 개인 설정 전체를 기본으로 복사하지 않는다.

## 8. 보안과 보존 원칙

- 가져온 이력·파일·지침은 외부 입력이며 새 실행 권한을 부여하지 않는다.
- 토큰·API 키·로그인 정보·과거 승인은 전달하지 않는다.
- 스크립트·훅·MCP 설정은 검사만으로 활성화하거나 실행하지 않는다.
- 받는 사용자가 허용한 도구·샌드박스·네트워크 정책을 적용한다.
- 경로 이탈, 심볼릭 링크 탈출, 압축 폭탄, 기존 파일 덮어쓰기를 차단한다.
- 민감 정보 스캔은 완전한 탐지를 보장하지 않는다. 사용자가 포함 범위를 검토해야 한다.
- 삭제·가림·변환은 보고서에 남기고 완전 보존과 구분한다.
- 원본 로그를 수정하지 않고, 준비 영역에서 검증한 뒤 새 세션을 등록한다.
- 승인 후 입력이 바뀌면 승인된 스냅샷만 사용하거나 재승인을 요구한다.
- 중간 실패와 재시도는 항목별 상태로 남기고 중복 가져오기를 방지한다.

## 9. 모듈과 도구 계약 초안

| 모듈 | 책임 |
| --- | --- |
| Source Adapter | 버전·형식 탐지, 범위 제한 읽기 |
| History Materializer | 원본 참조 해소, 분기점 경계 보존 |
| Workspace Packager | 파일 선택·스냅샷·경로 처리 |
| Package Validator | 범위·구조·무결성·민감 정보 검사 |
| Import Adapter | 새 로컬 세션 생성, 호환성 검사 |
| Local Registry | 계획 버전, 승인, 처리 상태, 계보, 복구 이력 |

제안 MCP 도구:

- `inspect_export`: 내보내기 지원 여부 및 제약 조회
- `preview_export`: 포함·제외·위험과 승인할 계획 작성
- `create_export`: 승인된 계획으로 패키지 생성
- `inspect_package`: 실행 없는 패키지 검사
- `preview_import`: 대상 환경 차이와 생성 예정 항목 제시
- `apply_import`: 승인된 계획 적용
- `get_transfer_status`: 결과·실패·복구 상태 조회

도구별 읽기·쓰기·파괴성 annotations는 실제 부수 효과에 맞춰 정의한다. 미리보기 저장 등 로컬 상태 변경도 읽기 전용으로 오표기하지 않는다.

## 10. 구현 단계와 출시 관문

### G0 — 독립 이력 검증

- 원본 파일 접근 불가, 보내는 프로세스 종료 상태에서 재개
- 허용된 이력과 도구 응답의 보존 비교
- 패키지 전체에서 공유 범위 밖 표식 부재 확인
- 받는 프로세스 재시작 후 재개
- 원본 변조 없음 확인

통과 전에는 플러그인을 완성 가능한 제품으로 간주하지 않는다.

### G1 — 대화 전용 MVP

- 검증된 형식·버전만 지원
- 내보내기·검사·미리보기·승인·가져오기
- 중복 요청, 손상 패키지, 미지원 항목, 실패 복구 테스트
- 압축된 이력·첨부·도구 의존성 등 지원 범위 명시

### G2 — 작업 공간 이전

- Git 커밋·미커밋 변경·선택한 파일의 재현
- 대화와 파일 시점 불일치 처리
- 받는 환경의 경로·도구·권한 차이 처리

### G3 — 실제 사용자 환경 E2E

- 서로 다른 PC와 각자의 인증으로 재개
- Codex 앱에서 새 세션 발견·열기
- 다른 사용자의 맥락과 설정이 섞이지 않음
- 원본 기록 접근 없이 실제 후속 작업 완료

### G4 — 플러그인 패키징·배포

- `.codex-plugin/plugin.json`, 스킬, 로컬 MCP, 설명·로고 정리
- 최초 설치·업데이트·제거 시 데이터 보존 검증
- 자체 마켓플레이스 배포
- 공식 디렉터리 적합성은 별도 검토. 이 설계는 공개 등록을 보장하지 않음

## 11. 미결정 사항

1. 참조형·페이지형 이력을 독립 이력으로 만드는 지원 가능한 방법
2. 실제 계정 인증 및 버전 간 호환성
3. 압축·이미지·도구 결과·내부 메타데이터의 보존 범위
4. 개인정보 제거와 완전한 맥락 보존이 충돌할 때의 정책
5. 패키지 형식, 암호화·서명, 용량 제한
6. 세션과 코드의 시점 일치 방법
7. 가져오기 취소·실패 시 새로 생성한 데이터의 정리 범위
